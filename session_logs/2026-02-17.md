## 2026-02-17 (Update - Full HTTP Capture)

### Goal
Make discovered endpoints immediately callable — pre-filled with real headers, body, query params, and a stored example response visible in the response pane.

### Changes Made

1. **Expanded `ProviderCapturedRequest` type**
   - Added `requestHeaders`, `requestBody`, `requestContentType`, `queryString`, and full `response` object (statusCode, statusMessage, headers, contentType, bodyPath, bodySize).
   - File: `packages/insomnia/src/provider-explorer/types.ts`

2. **Multi-hook capture pipeline + CDP response bodies**
   - Replaced single `onBeforeRequest` with 4 correlated webRequest hooks:
     - `onBeforeRequest` — filter + extract uploadData as request body
     - `onBeforeSendHeaders` — capture request headers (strip sensitive: cookie, authorization, etc.)
     - `onHeadersReceived` — capture response status + headers + content-type
     - `onCompleted` — commit to deduped map
   - Added CDP-based response body capture via `Network.getResponseBody`
   - Bodies written to `{userData}/responses/{uuid}.response` (same pattern as libcurl-promise)
   - Graceful fallback if CDP attach fails
   - `complete()` is now async, calls `collector.finalize()` which awaits pending CDP body fetches (3s timeout)
   - File: `packages/insomnia/src/main/provider-auth-in-window.ts`

3. **Rich request + response model creation**
   - `upsertDiscoveredProviderRequests` now populates headers, body (mimeType+text), and parsed query params
   - Uses actual captured URL (not template) so endpoints are immediately callable
   - Creates `Response` model records with `maxResponses=1` — response pane auto-loads via `getLatestForRequestId()`
   - File: `packages/insomnia/src/provider-explorer/generate-requests.ts`

4. **Browse button moved to top bar**
   - Removed non-functional Browser item from "+" dropdown menu
   - Added Browse button between provider dropdown and URL in top bar
   - File: `packages/insomnia/src/routes/organization.$organizationId.project.$projectId.workspace.$workspaceId.debug.tsx`

### Technical Findings

- **CDP `Network.enable` hangs before page load**: `sendCommand('Network.enable')` returns a promise that never resolves if the webContents hasn't loaded anything yet. Fix: attach debugger + register event listener synchronously, fire-and-forget `Network.enable` (no await). Events start flowing once the page becomes active. May miss response bodies for the very first page load but captures everything after.
- **Main process esbuild caching**: Changes to main process files (`provider-auth-in-window.ts`) require full app restart — Vite HMR only reloads renderer code. The esbuild step runs once at startup.
- **Persisted partition auto-login**: The partition `persist:provider-auth:{providerId}` retains cookies across sessions. If the user is already logged in, the site redirects to a success URL immediately, and the window closes before being visible. This is correct behavior — it captures requests during the brief load.

### Validation

- Type-check passed: `npm run type-check -w insomnia`
- Tested end-to-end: 21 Kosik API endpoints captured with headers, query params, and response data
- CDP body capture confirmed working (one expected third-party failure)
- Re-browse correctly replaces old captured responses (maxResponses=1 pruning)


## 2026-02-17 (Update - URL Path Tree Sidebar)

### Goal
Replace the flat endpoint list in provider mode with a collapsible URL-path-based tree view for navigating 20+ discovered endpoints.

### Changes Made

1. **New `ProviderUrlTree` component**
   - Parses request URLs into path segments, builds a trie, compresses single-child intermediate nodes (e.g. `api/front` instead of `api > front`).
   - Single-request leaf nodes render as one line (method badge + segment name) — no unnecessary branch header.
   - Multi-request or multi-child nodes get a collapsible branch with `▸`/`▾` toggle + segment name + muted full path.
   - Colored method badges (same palette as rest of app), requests sorted by method order.
   - All branches expanded by default, collapse state in local `useState<Set>`.
   - File: `packages/insomnia/src/ui/components/provider-explorer/url-tree.tsx`

2. **Conditional sidebar rendering**
   - Provider mode (`selectedProviderId !== 'backend'`): renders `ProviderUrlTree` instead of pinned list + virtualizer.
   - Backend mode: unchanged flat list with folders.
   - File: `packages/insomnia/src/routes/organization.$organizationId.project.$projectId.workspace.$workspaceId.debug.tsx`

### Technical Findings

- `Child.doc` union type includes `RequestGroup` which has no `.url` — requires type guard before accessing URL.
- Template variables (`{{ base_url }}`) in URLs need stripping before `new URL()` parsing.

### Validation

- Type-check passed: `npm run type-check -w insomnia`
